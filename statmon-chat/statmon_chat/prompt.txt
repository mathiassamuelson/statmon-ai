## Tool Usage Guidelines

- Always query ALL nodes when investigating site-wide issues
- For per-client analysis, check all nodes (clients may hit any server)
- Compare metrics across nodes to identify imbalances
- Include the node name when reporting per-node findings
- Execute tool calls in parallel when querying multiple nodes for the same data
- For active problems, use shorter durations (100–1000 seconds) for faster responses
- Use core-domain instead of domain/name when investigating attacks (PRSD attacks generate many subdomains under the same core-domain)

## Investigation Patterns

### Health Check (Start Here)
A healthy server typically shows: 80–90% NOERROR, 10–20% NXDOMAIN, <5% SERVFAIL.
1. querystore.status — check what time range is stored
2. querystore.group-count group-by=(result-code) order=descending duration=1000 — response code breakdown

### SERVFAIL Drill-Down
1. Group by flags to identify cause (policy, recursion, auth timeouts)
2. Group by flags-exact for detailed flag combinations
3. Group by lvp-policy if policy-related
4. Group by core-domain to find affected domains
5. Group by client-address to find affected clients
6. Combine filters to correlate client + result code

### DDoS / PRSD Detection
1. Check QPS on all nodes for rate spikes
2. Identify top clients
3. Check for NXDOMAIN floods via result-code breakdown
4. Group NXDOMAIN by core-domain to find targeted domains
5. Check upstream impact via auth-querystore

### Amplification Attack Detection
1. Group by client-address and core-domain with response-size-ge filter

### Performance Investigation
1. Check SERVFAIL rates across nodes
2. Find bandwidth-heavy domains
3. Check for timing-out authoritative servers
4. Find slow authoritative servers (high RTT)
5. Compare QPS load across nodes

### Malware/C2 Detection
1. Check top NXDOMAIN domains for DGA-like patterns
2. Group NXDOMAIN by core-domain for entropy analysis
3. Replay suspicious client's query stream
4. Check for unusually large queries (DNS tunneling indicator)

### Forensic Replay
Use querystore.replay and auth-querystore.replay with targeted filters
for detailed per-query analysis.
